## Causes and diagnostic evidence

The investigation reproduced numerical failures with the original public
`io.images.load` objects. Independent array calculations below isolate causes;
they are not evaluator workarounds or changes to acceptance thresholds.

### SimpleITK

Both registered affine-plus-B-spline failures occur on the oblique reference.
ITK returns the identity outside the B-spline's valid coefficient domain.
Brainhops extends the coefficient array with zeros and evaluates a partial
spline there. Zero extension and a validity mask have different effects.

At an affected point, the cubic grid coordinate is
`(0.99705818, 2.44508556, 2.5)` on a `(6, 6, 6)` grid. ITK's spline is the
identity there. Brainhops produces a maximum interior world-coordinate error
of 0.114045377 mm after the following affine. Applying the native validity rule
before that affine reduces this error to `3.2e-14` mm and the image difference
from three integer units to one.

[Brainhops issue #511](https://github.com/neuroscales/brainhops/issues/511)
tracks the transform-domain bug. Image clipping cannot supply this rule.

### MRtrix

MRtrix uses linear warp interpolation for composition, but `mrtransform`
resamples a warp onto a changed destination grid using cubic Hermite
interpolation. Brainhops uses linear interpolation for the loaded warp.
Changing the B-spline degree to three would still select the wrong kernel.

An independent tensor-product implementation of MRtrix's Hermite basis reduces
the inverse/downsampled-moving maximum interior error from 1.66465 to 0.000768.
The forward/oblique integer maximum drops from three units to one. The inverse
warp has a different grid from the fixed reference even for the native image
variant, which explains why that variant also fails.

[Brainhops issue #512](https://github.com/neuroscales/brainhops/issues/512)
tracks the interpolation mismatch. Its implementation needs to distinguish
composition from grid-dependent application.

### NiftyReg

The spline-velocity/downsampled-moving case fails with maximum interior error
0.106110. Brainhops integrates on the coarse control grid, whereas NiftyReg
expands the spline onto a dense reference grid before scaling and squaring.
Loading NiftyReg's independently integrated deformation reduces the error
against the original velocity expectation to 0.000580. This is a documented
numerical limitation, not an axis interpretation error.

[Brainhops issue #513](https://github.com/neuroscales/brainhops/issues/513)
tracks an explicit integration-grid choice. An image grid must not be silently
substituted for the coefficient grid.

### FSL

The quadratic and cubic coefficient failures on the oblique reference compare
different pipelines. FSL rasterizes the original spline and interpolates that
dense result while rebasing. Brainhops evaluates the spline directly at the
requested points. Independently following FSL's dense path reduces the maximum
interior differences from two and three units respectively to one unit. Only
three and five interior voxels then differ.

[Evaluation issue #6](https://github.com/neuroscales/brainhops-eval/issues/6)
tracks the distinction. The new `same-warp-` cases apply the identical native
rebased dense file through brainhops and FSL. The original direct-spline cases
remain present, with unchanged thresholds and explicit pipeline descriptions.

### elastix

All seven reader errors concern `HowToCombineTransforms "Add"`, which means
`T(x) = T1(x) + T0(x) - x`. Brainhops explicitly refuses this representation
because a sequence expresses composition. The existing
[brainhops issue #277](https://github.com/neuroscales/brainhops/issues/277)
now contains this run's evidence. Dropping the initial transform would change
the map, so the evaluation retains the failures.

## Remaining work

The brainhops issues require transformation-domain clipping, Hermite
interpolation, explicit velocity integration geometry, and additive
transformation support respectively. They remain unresolved by the diagnostic
calculations. Their implementations must preserve lazy Dask execution and
existing `clip=None` behavior. Native image reconstruction, geometry repair,
threshold widening and dropping transform components are not used here.
